# 裸K盘感项目（Naked-K Chart Intuition）

> 用多年的历史裸 K 线（只用 OHLCV，不加指标），让 AI 复现传奇交易员"把形态背下来"的判断能力——**检索与判别**路线，不是训练一个看图模型。

## 📌 新访客从这里读起

1. **`00_入口_读我先.md`** — 项目总入口，读完即可理解全貌（含最重要的一张"三件事状态表"）
2. **`results/M0_结论.md`** — 数据地基可靠性结论
3. **`results/pool_recheck.md`** — 核心假设的复核结论（哪些成立、哪些被证伪）
4. **`results/M1_构建报告.md`** — 检索层与界面的构建细节

## 一句话现状（2026-10）

| # | 是什么 | 状态 |
|---|---|---|
| **A 检索** | 给一段 K 线 → 1 秒内调出历史上最相似的几十段（116.6 万窗口 / 122 币 / 9 年 + 叠图界面 + 实时拉取 + 滚动补数据） | ✅ 已建成，可用 |
| **B 预测走势** | 相似段之后是涨是跌 | ❌ 已实证**不成立**（8 个定义 × 4 周期，IC 全线 ≈ 0，7/8 不如随机邻居） |
| **C 附带产物** | 插针捕捉（样本外亏大钱概率砍 42~58%）、币池治理、检索调仓位（已证否） | 🔶 独立成线，已结题 |

**核心教训**：形态检索能预测「会不会有大波动」，不能预测「是涨还是跌」；且"波动"信息几乎全部来自波幅那一个数字，不是形态。检索层的价值是"看得见、更守纪律"，不是"算得准"。

## ⚠️ 本仓库不含 41GB 数据

`data/` 目录（币安 1m/1h 历史 K 线 + FAISS 风格向量索引，共 41GB，单文件最大 2.1GB）**未上传**——GitHub 单文件上限 100MB，且对分析没有必要。数据可由代码重建：

```bash
python scripts/fetch_data.py      # 下载原始数据
python scripts/refresh.py --stage all   # 六步流水线：下载→合并→重派生→流动性→建索引→体检
python scripts/serve.py --open    # 启动叠图界面（或双击 启动界面.bat）
```

另有两份大体积交互式 HTML 报告（`results/blind_test.html`、`results/m1_blindtest/blindtest_20261004.html`）因体积原因留在本地。

## 技术要点（给分析者的索引）

- **路线**：不喂图，喂归一化后的 OHLCV 数值序列；检索式（最近邻）而非训练式
- **多视角相似度**：shape / raw / range / trend / vol / volume 六维向量分块索引（`scripts/m1_build_index.py`、`scripts/m1_lib.py`）
- **防自欺工具链**：point-in-time 币池、随机同数量对照、夏普标准误、走前向检验（`04`、`results/intrabar_ambiguity.md`）
- **界面**：`web/index.html` + `scripts/serve.py`（检索/叠图/实时拉取/截图通道）
- **数据源**：`data-api.binance.vision`（本机实测其余端点不通）
